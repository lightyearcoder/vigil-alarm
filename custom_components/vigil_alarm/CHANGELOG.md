# Changelog

## 0.5.6

- **Four new languages: German, French, Italian and Spanish** (next to English and Dutch), everywhere: the admin panel, the Vigil card, the touch panel, the notification and error texts, the Home Assistant screens (setup, options, entities, repairs) and the default sensor group names (for example *Außenhaut* / *Innenraum*). Admin panel and card follow your Home Assistant profile language; notifications follow the system language; a touch panel or tablet has the language chosen for it under *Panels* (the field now offers all six). Any other language still shows English.
- **The translations were written by Claude and are not checked by a native speaker.** Please report a clumsy or wrong text as an issue.
- **Touch panel:** the new languages need firmware 0.5.6. The texts are plain ASCII, like the Dutch ones (no accents on the screen: *Ueberbruecken*, *Desactive*). A panel with older firmware shows English for the new languages and keeps working. Firmware version 0.5.6; minimum ESPHome version unchanged.
- Tests: every language must have every text with the same placeholders (translations, messages, card, panel), and the phrases the card and the panel use to recognise Vigil's answers must be in the translations of every language.

## 0.5.5

- **The tamper entity also works for the 24-hour types.** The field *Tamper entity* (the tamper signal of the same device) is now there for *24 hours audible* and *24 hours silent* sensors too, not only for intrusion, fire, gas and water.
- **Permanent bypass per sensor.** A new tick on a sensor, *Keep the bypass after disarming (permanent)* (not for fire and gas): a manual bypass of that sensor then stays after disarming, also through a restart, until it is restored by hand. For a sensor that has been broken for a while. Without the tick nothing changes. A sensor that is permanently bypassed is shown on the *Overview* tab in a card *Permanently bypassed* (with *Restore*), and the Vigil card and the touch panel show *Bypassed: …* under *Disarmed*, so it is not forgotten. Config key `permanent_bypass`.
- **Notify groups and other notify entities as a channel.** The list under *Notifications* only offered `notify` services. It now also offers notify entities by entity id, such as a notify group made as a helper (`notify.family`); they are sent through `notify.send_message`. A notify entity gets a title and a message only, so the critical-alert format of the *Priority* option is not used for it. The form says so in a note under *Notify service* and *High priority*.
- **Screenshots of the new touch panel screens** (five mode buttons, the last alarm, Vacation, Custom and the 24-hour alarm) in the English and Dutch handbook and in the ESPHome README.
- **Touch panel:** under *Disarmed* the panel shows *Bypassed: Attic window* when a sensor is still bypassed (when it may show sensor names). New panel profile attribute `bypassed_text`. Firmware version 0.5.5: **flash the panels to get the line**; a panel with older firmware keeps working without it. Minimum ESPHome version unchanged (2026.9).

## 0.5.4

- **Two extra modes: Vacation and Custom.** Switch them on under *Settings → Modes* (the wizard has them too). Each has its own exit delay (60 and 30 seconds by default) and its sensors: put a sensor group in *Vacation* or *Custom* like in any other mode. The alarm entity offers *Arm vacation* and *Arm custom bypass* (the name Home Assistant gives to Custom; its state reads `armed_custom_bypass`), the service `vigil_alarm.arm` takes `vacation` and `custom`, the Vigil card and the touch panel have buttons and their own colours (teal and pink), users and panels can be limited to them like to the other modes, and the blueprints *Arm at a set time* and *Arm when everyone leaves* offer them. Existing installations are unchanged: both modes are off until you switch them on.
- **Two new sensor types: 24 hours audible and 24 hours silent.** *Audible* (for a panic button or a safe) always watches, in every state, and sounds the siren like a tamper contact; the cause is *24-hour alarm* (`alarm24`), it has its own binary sensor *24-hour alarm active*, and arming is refused while it is open. *Silent* (for a silent panic button, a freezer that gets too warm) never sounds: it is a technical alarm like water, with a message to the *Technical* channels and a line in the log.
- **Touch panel: buttons for the new modes and the alarm memory.** Up to five mode buttons in one row (the text gets smaller with more than three). Under *Disarmed* the panel shows *Last alarm: 14:03 Front door > Hall* when it may show sensor names (the same rule as the sensor list). The panel profile has a new attribute `last_alarm_text` and `modes_mask` has the bits 8 (Vacation) and 16 (Custom). **The panels have to be flashed to get the buttons and the line; a panel with older firmware keeps working with the three old modes.** Firmware version 0.5.4. Minimum ESPHome version: see the release notes.
- Panel simulator: scenes for five buttons, Vacation, Custom and the 24-hour alarm.

## 0.5.3

- **Alarm memory with the path.** From the start of an entry delay until the alarm is disarmed, Vigil writes down **every sensor that opens**, with time and room (the Home Assistant area), including sensors that do not count in the armed mode and bypassed ones. The *Overview* tab has a card **Last alarm** with the steps in order and for each whether it counted; the log has `alarm_sensor_seen` for the ones that did not (those that counted are `sensor_faulted` as before). The Vigil card shows *Last alarm: 14:03 Front door → Hall → Living room* and the alarm entity has the attribute `last_alarm`. The memory survives a restart and stays until it is cleared (no code needed: the Overview card in the panel, the service `vigil_alarm.clear_alarm_memory` or an automation) or the next alarm replaces it. The touch panel does not show it yet.
- **Cancel window for false alarms.** A valid code within 60 seconds after the siren goes off (setting *Cancel window*, 0 = off) marks the alarm as a false alarm: the siren stops, the memory says *cancelled* and a message goes to the alarm channels. New event `alarm_cancelled`. Intrusion alarms only.
- **Duress code.** A second code per user (*Duress code*) that disarms like the normal one, with nothing to see anywhere and a quiet siren, while the channels with the new kind of message **Duress** get a silent message. Vigil refuses a duress code when no such channel exists, and when it equals another code. The event `duress_used` is only in the log and goes to those channels, never to the event entity or the last event. A duress disarm never counts as a cancelled alarm.
- **Chime.** *Chime* on a sensor: when it opens with the alarm off, a short sound through a siren, switch, light, button or script chosen under *Settings → Chime*. No alarm, no message, no log line. The event `chime` is on the event entity for your own automations.
- New events: `alarm_cancelled`, `duress_used`, `alarm_sensor_seen`, `alarm_memory_cleared`, `chime`. New settings: `abort_seconds`, `chime_entity`, `chime_seconds`.

## 0.5.2

- **Practice mode.** On the Overview tab, *Start practice mode* (only while the alarm is off) lets the alarm run for real, but no siren sounds and no message goes out. Everything is in the log, marked `practice`; the panel shows a chip, the Vigil card a line, and the alarm entity has the attribute `practice`. It ends at the first disarm, after 30 minutes, or with *Stop practice mode*, and after a restart it is off. When it runs out while the alarm is armed, the alarm stays armed and works for real; if it is going off at that moment, siren and messages start then. New events `practice_started` and `practice_ended`.
- **Walk test.** *Start walk test* (Overview, or under *Sensors*): walk along the doors, windows and motion sensors with the alarm off and watch them being ticked off live. Only intrusion sensors take part (fire, gas, water and tamper sensors are always on and keep their own test). A sensor that does not react does not stop the test; the list at the end names what was missed. It ends when all sensors were seen, when you stop it, after 15 minutes, or when you arm. New events `walktest_started` and `walktest_finished`.

## 0.5.1

- **Installation wizard.** A wizard in the Vigil panel goes step by step through the modes, the sensors (Find sensors), the user (also made from a Home Assistant person), the notification channel (a phone with the app in one click), the siren and the panel, and ends with *Ready for use?*. It starts from the card *Set up Vigil* on the *Overview* tab while something is still missing, and can be opened again from *Ready for use?*. Every step can be skipped and the wizard comes back after a form is saved or cancelled. It uses the same forms as the tabs and saves nothing by itself.
- **New sensors found.** Vigil remembers which sensors it has already offered. Sensors that appear in Home Assistant later are counted: a badge on the *Sensors* tab and a card on the *Overview* tab, with *Review and add* (the list with only the new ones) and *Not now* (not announced again). Nothing is added by itself and there is no push message. After an update the sensors that exist are not announced as new.
- **The export file name has the time of the last save of the configuration** (not of the export): `vigil-alarm-2026-10-18-13-27-05.json`, in your local time. Exporting again without a change gives the same name. The file holds it as `changed_at`.
- **Fixed:** a dialog stays open when the panel reloads its data.

## 0.5.0

- **The log tells user and panel apart.** The *By* column of the *Log* tab is now two columns, *User* and *Via* (the panel or device it was done on), and the alarm entity has a new attribute `changed_via` next to `changed_by` (which is now only the user). The touch panel and the Vigil card show the two on separate lines. A change made without a code reads *unknown (no code)*. Unlocking the sensor list on a panel with a user code now logs that user (the installer code reads *installer code*). Bypasses that end because of a disarm name who disarmed and where; those that end because the sensor closed read *automatic*. The log export has the same split: `user` holds only the name and `source` the panel or device.
- **Back-up of the configuration at every change.** Whatever changes the configuration (an edit in the panel, an import, a restore, a change made outside the panel while Vigil was off), Vigil keeps the configuration as it was just before, with a summary of what changed. The last 10 versions are kept (a setting under *Settings*, 1 to 50). The new **Backup** tab lists them; *Restore* first shows what would change, and the restore itself is a change that can be undone the same way. After a save in the panel the message *Saved* has an *Undo* link. *View* opens a window with the change itself, and every version says which Vigil version made it. An update of Vigil that migrates your stored configuration keeps the configuration from before it as *Vigil update*; a version made by an older storage version can be viewed but not restored. Only the configuration is kept, not the state of the alarm.
- **Export and import of the configuration** as a file, from the *Backup* tab. An import shows what it would change and replaces the configuration only when you confirm; the present configuration is kept as a version first. The file holds no codes but does hold the hashed codes, the heartbeat address and the names of your notification services. A file from another storage format, or one that is not a Vigil export, is refused with a message and changes nothing.
- **Summary of a change before it is saved** for the changes that touch several things at once: a restore and an import show it and wait for your confirmation (the command `vigil_alarm/save_many` can preview too). The summary names what is added, changed and removed per kind (*Sensors: 3 added, Users: 1 changed*), and says how many settings change, never their values.
- **Why can't I arm?** A card on the *Overview* tab names, per sensor and per mode, what stops arming (an open tamper contact after an alarm, a sensor that does not respond and is set to block, a sensor set to refuse), with *Show* and *Bypass* buttons; a fire or gas sensor cannot be bypassed. On the touch panel and in the Vigil card a refused arm now says what stops it in the language of the panel (*Cannot arm: Front door tamper is open*) instead of a code, and offers one button, **Bypass and arm**. It asks for a code and needs the same rights as bypassing by hand; it never works for a fire or gas sensor, and nothing is bypassed when arming is refused for such a reason. The action `vigil_alarm.arm` has a new field `bypass_open` for the same in your own automations.
- **Panel firmware:** *Bypass and arm* is an amber, outlined button that replaces the tiles for a few seconds after a refusal; the panel simulator has a scene for it. Firmware version 0.5.0.
- **Fixed:** the message after a save (*Saved*, *Deleted*) could disappear at once because the panel redrew itself; it now stays for a moment.

Typing in a field elsewhere on the dashboard is left alone, and the code still shows as dots.
- **Choose per panel whether Vigil watches that it is reachable (*Watch whether this panel is reachable*).** A phone that is switched off, or a browser that is closed, gave you a Repair and a message *Panel not reachable* although nothing is wrong. For a tablet or phone the setting is now off by default (the form follows the kind of device until you change it yourself), for an ESPHome panel it is on. With it off there is no Repair and no message, the panel list says *Not monitored*, and the panel keeps working. **Entries you already had stay on.**
- **A new look for the Vigil card and the touch panel, one style for both.** A dark ground, calm cards and one colour per state (green disarmed, amber arming or something open, orange entry delay, red alarm, blue home, coral away, violet night, grey no connection). The state is a **ring with an icon**; during the exit and entry delay the ring becomes the countdown: the number of seconds in the middle, the ring running down from full to empty. The modes are tiles with an icon, *Disarm* is one wide button (black, with a green edge and green letters on the panel), and an alarm gets a red frame and a reddish ground. The card follows the width it is in (a phone column, a tablet in two columns) and the colours of your Home Assistant theme where it has them.
- **Touch panel: tabs *Alarm*, *Sensors* and *Info* at the bottom**, on every page except the keypad. The gear in the corner is gone: *Info* is a tab, and still opens only with the installer code. The *Sensors* tab shows the number of open sensors in a badge and is not there when the list is set to *never*. The keypad has real keys with icons (delete, confirm in green). The Home Assistant connection is an icon at the top right (red when the connection is gone).

- **Icons on the panel:** Material Design Icons, only the 24 glyphs the panel uses, in three sizes. ESPHome downloads the font file when you compile, so the first compile of this firmware needs internet access (the text still uses the built-in Montserrat, so there is no change in letters).
- **The size follows the screen:** the sizes of ring, keys and tabs are calculated from `screen_width` and `screen_height` of the hardware file, and the main page grows with the screen, so a wider panel later needs a hardware file, not a new design. Only the 480x480 Guition 4848 exists today; wider layouts are rendered and look right on a computer but are not tuned.
- **Panel simulator (`tools/panel-simulator/`):** renders every screen of the panel on a computer from the real YAML and `vigil_panel.h` with LVGL itself, in Dutch or English and at any size, so a change in the look can be seen without a panel. It made the pictures in the guides.
- **Guides updated** with pictures of the card and the panel (English and Dutch).
- **Please test the firmware on the panel and report:** the new screens are checked by ESPHome's configuration check and drawn by LVGL on a computer, but they have not yet run on the real panel (how it looks on the real LCD, touch accuracy, memory).

## 0.4.0

- **Panel register (tab *Panels*):** register a panel or tablet with a panel id (the name of the ESPHome device). Per panel: the modes it may arm in, whether it may disarm, bypass, silence or acknowledge, its language, whether and when it may show the sensor list (*always*, *only after unlocking*, *never*), how long it stays unlocked, an optional installer code of its own, and *blocked*. Vigil enforces this on the server: a call from a registered panel that its profile does not allow is refused and logged (`panel_refused`), and bypassing from a registered panel always needs a user code. Calls from sources that are not registered are not restricted.
- **Profile entity:** every registered panel gets `sensor.<panel id>_profile` with what it may do and show. Sensor names are only in it while the panel is unlocked (or set to *always*); those attributes, and the sensor-name attributes of the alarm entity, are kept out of the recorder history. It holds no code, hash or key.
- **Unlock and Clear lock:** two buttons per panel, only in the Vigil panel (administrators), not as Home Assistant actions, logged with the administrator (`panel_unlocked`, `panel_lock_cleared`). A panel can also be unlocked with its installer code through the new action `vigil_alarm.unlock_panel`; that never disarms the alarm.
- **One lockout timer per registered panel**, plus one shared by everything else, and a separate timer for each panel's installer code.
- **Panel out of reach:** after 10 minutes without a connection to the ESPHome device you get a Repair and a message on the fault channels (`panel_offline`, `panel_online`). The alarm state is never changed by it.
- **Tablet as a panel:** a panel in the register can be bound to a Home Assistant user (a tablet with Home Assistant's own alarm card). Vigil enforces the profile on the user behind the call, which Home Assistant fills in and which cannot be imitated with a `source` text; the tablet gets its own lockout timer whatever name it sends, is never an administrator for Vigil, and bypassing from it always needs a code. An administrator may be chosen too (see below). A [tablet guide](docs/tablet.md) explains the set-up and the limits (Home Assistant has no permissions per entity).
- **Vigil card for a dashboard:** `type: custom:vigil-card`, loaded by Vigil for every user (no resource to add). It asks Vigil which panel belongs to the logged-in user (a new command, open to non-administrators, `vigil_alarm/tablet`) and then follows that panel's profile: state and countdown, only the modes the panel may arm in, *Disarm*, a keypad that opens only when you press a button (never by itself, so during an entry delay or alarm you first see what is going on), bypass if allowed, and the sensor list after a user code or the installer code (until then only *how many* sensors are open). It only reads and calls the normal actions; Vigil still enforces the profile on the server. Dutch and English, following the panel's language.
- **Tablet offline:** the card says hello every minute. A tablet whose card has been silent for 10 minutes gives the same Repair and fault message as an ESPHome panel (`panel_offline`, `panel_online`); the panel list shows *Vigil card active*. Only tablets that have used the card are watched, and Vigil remembers that over a restart.
- **Phones and tablets are one thing with ESPHome panels:** an entry in the register can be bound to a Home Assistant account (a tablet on the wall or a housemate's phone) and follows the entry's own settings: modes, disarm, bypass, silence and the sensor list with the installer code. **Any valid user code works** on such a device and the history shows whose it was; each entry has its own lockout timer.
- **Only registered accounts may operate:** as soon as one account is registered, every other ordinary Home Assistant account is refused before its code is looked at (`user_refused`, never counted towards a lockout). Administrators, automations, scripts and ESPHome panels are untouched, and an installation without a registered account does not change at all.
- **Advice in the guides:** give an administrator a second, ordinary account for daily use, lock the kiosk browser, and turn on *Code required to arm* to keep a passer-by from arming.
- **ESPHome firmware reads the profile:** a new folder structure (`esphome/vigil_alarm/` holds the firmware and the hardware file `guition-4848.yaml`, the folder above it only your device file). The panel takes everything it may do from its profile (modes, disarm, bypass, language, sensor list, unlock time) and uses the ESPHome device name as panel id and `source`; the substitutions `source`, `language`, `allow_bypass`, `sensor_list` and `sensor_unlock` are gone. A panel that is not registered shows *Not linked*, a blocked panel *Blocked*. The settings page with the language buttons is replaced by an info page (IP address, signal, uptime, firmware, panel id) behind the panel's installer code; the same code opens the sensor list, and bypassing always asks a user code. While locked, the panel shows only how many sensors are open. The firmware reports *Hardware ID*, *Capabilities*, *Firmware version* and *Profile version*, and screen sizes are set in one place (the hardware file).; please test and report.
- **Adding a panel is split by kind of device:** a first choice, *ESPHome panel* or *Tablet or phone running Home Assistant*, shows only the questions that fit. A tablet or phone asks for the Home Assistant account only (its panel id is made from the name). The language of a new panel starts as the language of the person who adds it; the choice *Home Assistant language* is gone.
- **No more *expected hardware* field:** the hardware the firmware reports is still shown on the panel card, but nothing needs to be filled in and there is no hardware advice any more.
- **ESPHome example:** updates over Wi-Fi now use `encryption` under `ota` (the key of the `api`) instead of an OTA password, as ESPHome advises; it saves memory and needs one secret less. The warnings about GPIO19 and GPIO20 are explained in the ESPHome README: the board wires them, they cannot be avoided.
- **The touch that wakes the screen is not a press:** while the screen is dark a see-through layer lies over the panel, so the first touch only switches the light on and does not also press the button under your finger. The layer goes when you lift the finger. A hardware file that calls `wake` on touch keeps working.
- **An administrator account may be chosen for a tablet or phone** (shown as *(admin)* in the list). That is the administrator's own responsibility, and the guides say so: the settings of the panel apply to everything that account does, on every device it is logged in on. On the panel Vigil gives it no administrator rights (a code is always needed to disarm and bypass, and tamper bypass needs a user with that right).
- **New scripts are not cached by the browser:** the address of the panel and the card now contains a fingerprint of the files, so a changed version is loaded without a hard refresh.
- **Countdown of the exit and entry delay is right on the panel and the card:** with 60 seconds it starts at 60 and the alarm is on at 0. Before, the panel counted against its own clock, which could be a few seconds off. Vigil now sends the seconds left (attribute `delay_left` on the alarm entity) and the panel and card count down from there.
- **Main page while disarmed shows only how many sensors are open** (panel and card), also after the sensor list was unlocked. The names are on the sensor list.
- **No false "sensor lost" messages after a restart of Home Assistant (Settings, card *Start-up*):** after the first 10 seconds Vigil already follows the sensors that are there, but a sensor that is still "unavailable" (MQTT or Zigbee that is still starting) is left alone: not reported as lost and not an alarm. As soon as all sensors are there, or after the wait (default 120 seconds, 10 to 900), Vigil reports the ones that are really gone. The event `startup_settled` in the log says how long it waited and which sensors were still missing. Reloading Vigil while Home Assistant runs does not wait. Only sensors are covered: other start-up reports (a panel that is out of reach, a failing heartbeat) keep their own timing.
- **Lock messages (follow-up):** the wrong code that starts a lock now says so at once ("Too many wrong codes. Try again in 5 min"), instead of "Invalid code" and a lock that only shows at the next try. The same message names the minutes still to wait (rounded up), and a permanent lock says an administrator must unlock it. The panel and the card show Vigil's refusals (invalid code, locked, no right to bypass, blocked, ...) in the language of the panel, whatever language Home Assistant answered in; before, an English text could appear on a Dutch panel.
- **Sensor list with a user code; bypass is a right:** the sensor list of a panel or the card now opens with the code of any Vigil user (or the installer code); the info page still needs the installer code. The action `vigil_alarm.unlock_panel` got an optional `scope` (`sensors` or `info`, default `info`, so older firmware keeps working). A wrong code for the list counts on the same timer as the other user codes of the panel. Users have a new right, *May bypass sensors*: without it a user can neither bypass nor restore a sensor, even with a right code (whoever may bypass may also restore; a tamper sensor needs *May bypass tamper* for both). Users saved before this existed keep the right until you untick it. The keypad says *Enter your user code* for the list.
- **Locking in steps (Settings, new card *Locking*):** seven settings. By default 3 wrong codes lock a panel for 5 minutes; after that 2 more wrong codes lock it for 15 minutes, then 2 more for 60 minutes, and 1 more wrong code locks it for good. A permanent lock only goes away with *Clear lock* at the panel (the button already existed) and the panel shows *Locked for good*. A right code sets the count and the step back to zero, and *Clear lock* does as well. The step, the count and a permanent lock are kept over a restart. The new event `code_locked_permanent` is also sent to the fault channels. The shared timer for everything that is not a registered panel never locks for good (nobody could lift it) and repeats the last wait. The old rule (5 wrong codes within 5 minutes) is gone; the count no longer expires by time.
- **Screen settings for the panels (Settings, new card *Panel screen*):** *Screen off after* (seconds without touch, 5 to 3600, default 30) and *Also let the screen go dark during an alarm* (default off: the screen stays on while the alarm is going off, so ALARM and its cause stay visible). The panel reads both from its profile entity (`screen_off_seconds`, `screen_off_on_alarm`). The screen only goes dark in a steady state (alarm off or fully armed), never while it counts down to arm or to enter. A half typed code, the list or the info that stays open too long first returns to the main page, and the screen goes dark after the same time again. The firmware substitution `backlight_timeout` is now `backlight_timeout_seconds` and only the start value until Vigil has told the panel.
- **No more jumping screen before it goes dark:** the panel used to return to the main page after 30 seconds and, during an entry delay or alarm, open the disarm keypad again at the very moment the light went out. It now does that after the screen is dark, so you see no jump and the keypad is simply there when you touch the screen. The setting `idle_timeout` is gone: the time is `backlight_timeout`.
- **Info page of the panel:** the back button now shows its arrow.
- **Keypad says which code:** under the code the panel and the card show *Enter your user code* or *Enter the installer code*. The code that unlocks the sensor list and the info page is now called the **installer code** (before: administrator code).
- **Sensor list in a useful order:** on the panels and the card the sensors that are most likely to be bypassed come first: open sensors that can be bypassed, then unreachable ones, then open fire and gas sensors (which cannot be bypassed), then bypassed ones, then the closed ones. Alphabetical within each group.
- **A panel always has a language:** the choice *Home Assistant language* is gone. A new panel starts with the language of the person who adds it (Dutch if that is Dutch, English otherwise). Panels made earlier with the old choice keep working.
- **Profile sensor with an old id is renamed:** a profile sensor made by an earlier build keeps the entity id it got then (Home Assistant never renames by itself), so the firmware could not find it. Vigil now renames it to `sensor.<panel id with underscores>_profile` at start-up, if that id is free. The *Not linked* screen of the panel also shows the sensor it looks for.
- **Changed:** the profile entity id is now `sensor.<panel id with underscores>_profile`, independent of the name you give the panel. The alarm entity no longer has the attributes `open_now_text`, `open_sensors_text`, `faults_text` and `panel_sensors` (they are in the profile of a panel, while allowed).

## 0.3.2

- **The code lock now survives a restart.** After five wrong codes within five minutes the lock lasts five minutes, also when Home Assistant restarts or Vigil is reloaded in that time. A stored lock is never longer than five minutes, even when the clock changes. The lock is also reported as a message on the *Fault* channels, and the event `code_locked` now carries the timer and the number of minutes.

## 0.3.1

- **Settings in sections:** the Settings tab is now one card per subject (modes and delays, codes, batteries, event log, self-test, heartbeat), each with a line of explanation. The hours for the automatic siren test only show when that option is on; the hours you set are kept.
- **Heartbeat:** Vigil can call a web address of your choice at a fixed interval (default every 5 minutes, also when the alarm is disarmed), so a monitoring service outside your house reports when Home Assistant, the computer or your internet stops. It is not tied to any service; the manual works out Healthchecks.io as an example. The address is treated as a secret and is kept out of the log, the diagnostics and the Repairs. A *Heartbeat* card on the Overview shows the last success and failure and has a *Test now* button; three failures in a row give a Repair.
- **Self-test:** a quiet daily check that your notification services still exist and your sirens can be reached (only a missing channel gives a message and a Repair), and a monthly siren test reminder (interval is a setting, 0 = off) with a **Test siren** button on phones using the Home Assistant app. A second reminder follows after 3 days and a Repair after 7 more. Optionally Vigil sounds the siren itself within hours you set (off by default). A *Self-test* card on the Overview shows the last check and the next test; *Test siren now* sounds the siren for a moment. Three new events (`selftest_checked`, `selftest_reminder`, `selftest_siren_tested`) are logged.
- **Event log:** a new *Log* tab shows everything Vigil publishes as an event, newest first, and keeps it for 90 days (a setting, 1 to 3650 days). Home Assistant's own logbook keeps ten days by default. The log holds no codes. Download it as **JSON Lines** (one object per line) or **CSV** (RFC 4180); times are RFC 3339 in UTC, with the fields `time`, `event`, `source`, `user`, `item`, `result` and `detail`, so any standard tool can read it. The log survives restarts and updates.

## 0.3.0

- **Find sensors:** *Sensors → Find sensors* lists the door, window, motion, smoke, gas, water and tamper sensors Home Assistant already knows, with the battery and tamper sensor of the same device. It works on standard Home Assistant data only (device class, same device, entity category, unit), so it is not tied to one integration. Tick what you want and add several in one go; nothing is saved until you confirm, and if one fails nothing is saved. Doors can be marked as an entrance (entry delay).
- *Copy discovery data* copies an anonymous list (no names or addresses) that helps to test an integration.
- **Ready for use?** on the Overview tab names what is missing (no sensors, no sensor groups, a mode nothing watches, no user with a code, no notification channel, no siren, sensors without a battery sensor, tamper sensors that are not connected), each with a button to the right place.
- **Create default groups:** Perimeter (doors and windows, all modes) and Interior (motion, Away), or the Dutch names when Home Assistant is set to Dutch. Only kinds you do not have yet are added.
- A phone with the Home Assistant app is offered as the first notification channel, with a test message.
- A one-sentence summary under each sensor name: how it reacts and when it is watching.
- **Copy dashboard:** a dashboard with this installation's own entity ids.
- A battery sensor can also be a "battery low" on/off sensor, for devices that report no percentage.
- Diagnostics (Download diagnostics) without codes, tags or names of people.
- **Repairs:** real faults (a sensor that cannot be reached, a low battery, a siren that is unavailable or has lost mains power) appear under Settings > System > Repairs and disappear by themselves when fixed. Missing settings are not repairs; see *Ready for use?* in the panel.
- A "new" badge on the About tab after an update.
- New troubleshooting page (My alarm does not do what I expect) and an updated test guide.

## 0.2.0

- **Breaking:** the integration is now called `vigil_alarm` (it was `vigil`), and entity ids always end on the English name. Remove the old Vigil integration from Settings > Devices & services, restart Home Assistant, add Vigil Alarm again, and update your own automations and dashboards to the new entity ids.
- An entity can only be used by one sensor, so a door contact or its tamper contact can no longer be added twice by accident.
- A sensor can have a tamper entity: Vigil adds the tamper sensor for it by itself (always watching, its own bypass switch), so a door contact with a tamper contact needs one form instead of two.
- The tables for sensors, groups, rules, users, notifications and sirens use the full width of the page.
- The sensors table has a separate Battery column; a level at or below the battery limit is highlighted.
- The sensor form has a short hint and an (i) button with the full explanation of "If open when exit delay ends" and of the tamper entity.
- The panel's edit, copy, delete and test buttons are icons, so the tables have more room; users can no longer be copied.
- New About tab in the Vigil panel: logo, version and Home Assistant version side by side, links with icons, release notes and a button that copies the details for a bug report.
- Touch panel for ESPHome (Guition 4848): arm, disarm, sensors and bypass, Dutch and English. See `esphome/`.
- New actions `vigil_alarm.arm` and `vigil_alarm.disarm`, and an optional `source` on the control actions: the history shows who did it, for example "Anna (panel garage)".
- The touch panel shows the list of sensors only after a code by default (`sensor_list`: `code`, `always` or `never`), and no sensor or people names on the main page while the alarm is on. New action `vigil_alarm.check_code`.
- The minimum length of a code is a setting (4 to 12, default 4); shorter codes are refused.
- Entity ids always end on the English name (`..._fire_alarm`, `..._bypass`, `..._status`), whatever language Home Assistant runs in; the shown names stay translated.
- The alarm entities for intrusion, fire, gas, tamper and water always exist, also without a sensor of that class.
- New event `code_rejected` for a wrong code, with the source but never the code.
- Five wrong codes within five minutes lock all codes for five minutes (event `code_locked`), so a PIN cannot be guessed through the services.
- Bypassing needs a code only when arming does (a code is required to arm). Silence and acknowledge always need one.
- Extra attributes on the alarm for displays: `mode` and text versions of the open sensors, faults and the sensor list.
